# sshfwd

`sshfwd` resolves services through Consul and opens local port forwards with OpenSSH.

## Install

```console
go install github.com/0neSe7en/sshfwd@latest
```

Requires `ssh` locally and `curl` on the remote SSH host.

## Usage

```console
sshfwd <host>
```

`<host>` is an alias from `~/.ssh/config`. The tunnel runs in the foreground; press `Ctrl+C` to close it.

Export the current resolved endpoints as SSH config:

```console
sshfwd export <host>
```

List configured host aliases in alphabetical order:

```console
sshfwd hosts ls
```

## Quick start

Configure an SSH host in `~/.ssh/config`:

```sshconfig
Host staging
    HostName bastion.example.com
    User deploy
```

Create `~/.ssh/sshfwd.toml`:

```toml
[resolvers.consul]
type = "consul"
address = "127.0.0.1:8500"

[hosts.staging]
resolver = "consul"

[hosts.staging.forwards]
web = "3000"
```

Run:

```console
sshfwd staging
```

`sshfwd` resolves the Consul service `web` and forwards `127.0.0.1:3000` to the resolved service endpoint.

Services resolve independently. `sshfwd` writes resolution errors to stderr and opens the tunnel with the services that resolved. When every service fails to resolve, OpenSSH still starts with forwards from the normal SSH config.

## Configuration

Configuration is loaded from `~/.ssh/sshfwd.toml`.

### Resolvers

Define named resolvers under `resolvers`:

```toml
[resolvers.consul]
type = "consul"
address = "127.0.0.1:8500"
```

A host references a resolver by name:

```toml
[hosts.staging]
resolver = "consul"
```

Resolver names are arbitrary. The Consul address must be reachable from the remote SSH host.

### Forwards

Map Consul service names to local listeners:

```toml
[hosts.staging.forwards]
web = "3000"
admin = "127.0.0.1:3001"
```

A bare port such as `"3000"` binds to `127.0.0.1`. Use `"0.0.0.0:3000"` for another bind address or `"[::1]:3000"` for IPv6. Ports must be between `1` and `65535`.

### Forward sets

Forward sets let multiple hosts share the same services and local ports:

```toml
[forward_sets.web]
web = "3000"
admin = "3001"

[forward_sets.databases]
postgres = "5432"
redis = "6379"

[hosts.staging]
resolver = "consul"
forward_sets = ["web", "databases"]

[hosts.production]
resolver = "consul"
forward_sets = ["web", "databases"]
```

Sets are merged from left to right. A later set overrides an earlier value for the same service.

### Host overrides

Host-specific forwards are applied after forward sets. They can override shared values or add services:

```toml
[hosts.staging]
resolver = "consul"
forward_sets = ["web", "databases"]

[hosts.staging.forwards]
web = "4000"
debug = "4001"
```

## SSH config

Normal SSH options continue to work, including `ProxyJump`, identities, and existing forwards.

```sshconfig
Host staging
    HostName bastion.example.com
    User deploy
    DynamicForward 127.0.0.1:1080
    LocalForward 127.0.0.1:4646 192.168.0.1:4646
```

Configured `LocalForward`, `RemoteForward`, and `DynamicForward` entries remain active when running `sshfwd staging`.

`sshfwd` reports configured local-port conflicts before starting SSH. If another process already occupies a port, OpenSSH prints its normal bind error and keeps the SSH session running.

## Export

```console
sshfwd export staging
```

Example output:

```sshconfig
# Generated by sshfwd; Consul endpoints are a point-in-time snapshot.
Host staging
    LocalForward 127.0.0.1:3000 192.168.0.1:8080
```

Exported endpoints are a point-in-time snapshot of Consul results.
